# دليل رفع الموقع على دومين واستضافة (للعميل يشتغل بجد)

## الفكرة العامة

```
الزائر ← Cloudflare (مجاني: يحمي ويخزّن الصور والملفات قريب من الزائر)
       ← nginx على السيرفر (يوزّع الطلبات ويقدّم صور السيارات مباشرة)
       ← تطبيق الموقع (Node.js) شغّال منه نسختين بالتوازي
       ← قاعدة البيانات (ملف SQLite) + مجلد الصور على ديسك السيرفر
```

## ايه اللي اتعمل في الكود عشان يتحمّل ضغط

| المشكلة | الحل |
|---|---|
| كل كارت كان بيحمّل صورة كبيرة (حتى 1600px) | كل صورة بتتحوّل لـ WebP + **صورة مصغّرة 640×480 للكروت** (~35 KB بدل ~300 KB) |
| قايمة السيارات بطيئة مع الكتالوج الكبير (كان 1.2 ثانية) | استعلام جديد + فهارس مخصوصة: **0.07 ms بدل 3.9 ms** |
| آلاف الزوار بيطلبوا نفس القايمة | كاش في الذاكرة 10 ثواني للزوار العاديين (بيتمسح فورًا في النسخة اللي حصل عليها التغيير، والنسخة التانية بتلحق خلال 10 ثواني على الأكتر) |
| رفع صور كتير في نفس اللحظة يكلّ الذاكرة | أقصى 4 عمليات رفع بالتوازي والباقي في طابور، والذاكرة ثابتة ~100 MB |
| ملف مزيف أو تالف على أنه صورة | كل صورة بتتفك وتتعاد فعليًا؛ اللي مش صورة حقيقية بيترفض |
| صور الموبايل فيها موقع GPS | بيتشال تلقائيًا من كل صورة |
| سكريبت أو مهاجم بيضرب الموقع | حد للطلبات لكل زائر + حد لتسجيل الدخول + حد رفع لكل حساب + حد سيارات لكل تاجر |
| السيرفر يقع أو يتعمله restart | PM2 بيعيد تشغيله لوحده، وبيقفل قاعدة البيانات بشكل نضيف |

## الأرقام اللي اتقاسّت فعلًا

اختبار على كتالوج **5,000 سيارة و15,000 صورة**، **64 مستخدم متزامن**، نسخة واحدة من التطبيق (على لاب قوي 12 نواة، وأداة الاختبار شغّالة على نفس الجهاز):

| الطلب | قبل التحسين | بعد التحسين | مع الكاش |
|---|---|---|---|
| قايمة السيارات (صفحة 1) | 54 طلب/ثانية (زمن 1.17 ث) | 1,023 (61 ms) | **5,285** (11 ms) |
| بحث نصي | 84 (0.76 ث) | 297 (0.23 ث) | 6,036 |
| مزيج واقعي (60% قوايم / 20% تفاصيل / 20% صور) | 796 | 920 | **3,803** |
| رفع 12 تاجر لسيارات (6 صور لكل واحدة) في نفس اللحظة | — | كلهم نجحوا في 4.6 ثانية | — |

**تحذير أمين:** السيرفر الحقيقي (2 نواة) أبطأ من اللاب ده، فاقسم الأرقام على 3–4. حتى كده، لسيرفر 2 نواة بنسختين من التطبيق مع Cloudflare، **التقدير المريح حوالي 100–300 ألف زيارة في اليوم** (تقدير مش ضمان). أول ما الزيارات تفوق ده، مش المشكلة في الكود؛ الحل ترقية السيرفر (نواتين زيادة + `WEB_CONCURRENCY`)، وبعده نقل الصور لتخزين سحابي وقاعدة البيانات لـ PostgreSQL. **قيس بعد النشر** بدل ما تعتمد على تقديري.

## اللي العميل لازم يدفعه (أسعار تقريبية، اتأكد منها وقت الشراء)

| البند | التكلفة التقريبية | ملاحظة |
|---|---|---|
| **دومين** `.com` | 10–15 دولار في السنة | Namecheap أو Cloudflare Registrar (بسعر التكلفة). دومين `.com.eg` من مسجّل مصري بسعر مختلف. |
| **سيرفر VPS** | 6–12 دولار في الشهر | المواصفات الدنيا: **2 vCPU، 4 GB RAM، 60 GB SSD، Ubuntu 24.04**. شركات: Hetzner (غالبًا الأرخص)، Contabo، Hostinger VPS، DigitalOcean/Vultr (أغلى). اختار موقع في **أوروبا (فرانكفورت)** أو الأقرب لمصر. |
| Cloudflare (DNS + حماية + CDN + HTTPS) | **مجاني** | |
| شهادة HTTPS | **مجانية** | Let's Encrypt |
| إيميل الإشعارات (Gmail) | **مجاني** | App Password لحساب الإيميل |
| واتساب | **مجاني** | لينكات wa.me |
| نسخة احتياطية خارج السيرفر | 0–3 دولار في الشهر | Backblaze B2 أو Cloudflare R2، أو لقطات الشركة نفسها (+20% تقريبًا) |

**الإجمالي حوالي 8–15 دولار في الشهر + الدومين مرة في السنة.**
لو الميزانية أقل: سيرفر 2 vCPU / 2 GB يشتغل، بس الرفع هيبقى أبطأ ومحتاج swap (السكريبت بيضيفه).

## خطوات النشر (بالترتيب)

### 1) اشتري وجهّز
1. اشتري **الدومين**، واعمل حساب على **Cloudflare** (مجاني) وأضف الدومين فيه واتبع خطواتهم لتغيير الـ nameservers عند المسجّل.
2. اشتري **VPS** بنظام Ubuntu 24.04. هيوصلك على الإيميل: **عنوان IP** وباسوورد `root`.
3. في Cloudflare ← DNS: أضف سجلين من نوع **A**: الاسم `@` والاسم `www`، القيمة = IP السيرفر، وسيب السحابة البرتقالية **شغّالة** (Proxied).

### 2) ارفع المشروع للسيرفر (من الويندوز بتاعك)
افتح PowerShell:

```bash
scp D:\moamenoon\moamenoon-cars.zip root@IP_السيرفر:/root/
ssh root@IP_السيرفر
```

### 3) على السيرفر
```bash
apt-get update && apt-get install -y unzip
unzip moamenoon-cars.zip -d /root/
cd /root/moamenoon-cars
DOMAIN=your-domain.com EMAIL=you@gmail.com bash deploy/setup-server.sh
```
السكريبت بيثبّت كل حاجة (Node 22، nginx، PM2، جدار حماية، نسخ احتياطي يومي 03:30، وشهادة HTTPS لو الدومين ظاهر للسيرفر) ويشغّل الموقع.

### 4) الإعدادات السرية
```bash
nano /var/www/moamenoon/.env
```
اضبط:
- `ADMIN_PASSWORD=` باسوورد قوي للأدمن.
- `SMTP_PASS=` الـ App Password بتاع Gmail (عشان إيميلات القبول والرفض تتبعت فعلًا).
- `TRUST_PROXY=2` (لأن Cloudflare + nginx قدام التطبيق).

بعدين:
```bash
sudo -u moamenoon pm2 reload moamenoon
```

### 5) Cloudflare
- SSL/TLS ← اختار **Full (strict)**.
- (اختياري) Caching ← Cache Rules: خزّن `/uploads/*` مدة شهر.

### 6) اختبر
- افتح `https://your-domain.com` وسجّل دخول كأدمن (`moamnoon.co@gmail.com`).
- `https://your-domain.com/api/health` لازم يرد `{"ok":true}`.
- سجّل تاجر تجريبي، وارفع سيارة بصور، وقبلها من لوحة الأدمن، وتأكد من رقم الواتس. بعدها **امسح التاجر التجريبي** من لوحة الأدمن ← المستخدمين (بيمسح سياراته وصوره معاه).

**ملحوظة:** الموقع بيبدأ على السيرفر **فاضي**، فيه حساب الأدمن بس، والسيارات بيرفعها الأدمن والتجار.

## بعد النشر

| المهمة | الأمر |
|---|---|
| متابعة الأخطاء | `sudo -u moamenoon pm2 logs moamenoon` |
| حالة الموقع والذاكرة | `sudo -u moamenoon pm2 monit` |
| تحديث نسخة جديدة | ارفع الـ zip الجديد وفكه في `/root/moamenoon-cars` ثم `bash deploy/update.sh` (بيعمل نسخة احتياطية الأول، وبيحدّث من غير ما الموقع يقف) |
| نسخة احتياطية يدوية | `sudo -u moamenoon moamenoon-backup` (بتتحط في `/var/backups/moamenoon`) |
| مراقبة | حط `https://your-domain.com/api/health` في UptimeRobot (مجاني) ينبّهك لو الموقع وقع |
| اختبار حمل | `npm run loadtest -- http://localhost:3000 30 8` على السيرفر نفسه (الموقع بيحد الطلبات لكل IP فهيظهر 429 لو اتخطى الحد، وده الطبيعي) |

**مهم جدًا:** انسخ `/var/backups/moamenoon` **خارج السيرفر** بانتظام (جهازك، أو Google Drive بـ rclone). النسخة اللي على نفس السيرفر مش بتنفع لو السيرفر نفسه ضاع.

## استرجاع من نسخة احتياطية
```bash
sudo -u moamenoon pm2 stop moamenoon
cp /var/backups/moamenoon/db/app-التاريخ.db /var/www/moamenoon/data/app.db
rsync -a /var/backups/moamenoon/uploads/ /var/www/moamenoon/data/uploads/
sudo -u moamenoon pm2 start moamenoon
```

## قبل ما تسلّم للعميل
- [ ] حطيت `ADMIN_PASSWORD` قوي (مش نفس الباسوورد اللي جربت بيه على اللاب).
- [ ] اختبرت إيميل الموافقة على تاجر (وصل فعلًا).
- [ ] دخلت من موبايل حقيقي على `https://`.
- [ ] عملت نسخة احتياطية يدوية وتأكدت إنها ظهرت.
- [ ] اتأكدت إن رقم واتساب المعرض وروابط الفيس والإنستا صح (`public/js/config.js`).

## أمانة في الآخر
- السكريبتات اتفحصت كتابيًا (syntax) واتجرّب الأمر الأساسي للتطبيق والنسخ الاحتياطي، لكن **`setup-server.sh` ما اتشغّلش على سيرفر Ubuntu حقيقي** (مفيش سيرفر عندي). جرّبه أول مرة على سيرفر رخيص قبل ما تستخدمه مع العميل، ولو ظهر أي خطأ ابعتلي رسالته وأصلحه.
- أرقام الأداء على جهاز التطوير، مش على السيرفر اللي هتشتريه.
